# Blender 模型输入格式（v1）

此格式只承载已经由用户确认或从可靠 CAD 尺寸中取得的设计几何，不负责从截图猜测尺度、墙体性质或施工条件。项目 JSON 与生成模型放在该对话的 workspace；技能目录只保存格式规范、脚本和通用模板。

## 几何来源追溯（用户确认的必需项）

正式新建或修改几何时，用顶层 `source_ledger` 记录来源，并在每个房间、墙边、洞口、家具和固定构件上用 `source_refs` 指向来源 ID。来源类型可为 CAD、注释器标注、用户明确指令或合成测试；合成数据须标为 `synthetic_fixture`，不能冒充 CAD 依据。`locator` 应足以让人回到来源位置核对；可附相对几何 JSON 的证据文件路径 `artifact` 和其 SHA-256。

运行 `scripts/audit_geometry_sources.py --geometry <几何JSON>` 做只读核查：退出码 0 表示引用齐全且证据哈希匹配，2 表示缺失/未引用来源或几何实体只有注释器标注来源，1 表示引用结构或哈希错误。注释器标注只表达设计意图/像素区域，不能单独证明毫米尺寸或CAD几何；真实项目中每个房间、墙边、洞口、家具和固定构件须至少有一条 `cad` 或 `user_instruction` 来源，`annotation` 可并列补充其用户意图。`synthetic_fixture` 仅可用于合成回归测试，不得据此把测试几何标为真实项目已确认。非0时不得记录确认凭据或正式写出DXF/Blender/渲染提示词。审计只验证引用及文件版本，不证明 CAD 解释正确、批注理解正确或几何已获用户确认；旧JSON仍可预览，但须补来源、重新取得对应版本确认后才能正式写出。

## 坐标与单位

- `units` 固定为 `mm`；平面坐标为 `[x, y]`，Z向上。Blender内部使用米。
- 房间 `polygon` 是按边界顺序排列的闭合多边形顶点，不重复首点。
- 每个房间的 `walls` 与 polygon 边一一对应：`walls[i]` 从 `polygon[i]` 连到 `polygon[(i+1) % n]`。
- 相邻房间的共墙应在双方用完全相同的中心线端点描述，厚度与开口也须一致；反向边的开口起点按各自边方向填写。Blender 与 DXF 导出会将该共墙只生成一次；发现厚度/开口冲突会停止并报出房间与边号，回到确认图纸核对，不会任选一侧。
- 每条墙的 `openings` 可选；`start_mm` 是从该墙起点沿墙量取的距离，`width_mm`、`sill_mm`、`height_mm` 为洞口宽、窗台高、洞口高。门通常 `sill_mm: 0`。只有 CAD 明确或用户确认开启信息时，门洞才可附 `door_swing: {"hinge":"start|end", "side":"left|right"}`；hinge 是门洞沿墙方向的起/终端，side 是面向该墙起点至终点方向时的左/右侧。缺省时只生成门框和空洞口，不自动补门扇。共墙需在两侧描述同一实际铰链/开启方向；反向边按物理位置归一核对。
- 公共校验器 `scripts/geometry_utils.py` 会拦截房间自交/重叠、零面积、无效坐标、洞口越界/重叠、家具/固定构件占地超出所属房间、家具彼此占地重叠、家具与固定构件在平面和高度上相交及构件顶部超过墙高；仅接触边缘不算占地重叠。需依据用户确认图纸调整输入后再生成。
- 当前 v1 支持直线墙、垂直洞口、矩形家具占位体，以及明确录入的柱/竖井/梁等矩形固定构件；不从图纸自动识别结构。Blender 门洞默认只绘门框，只有用户/CAD明确给出 `door_swing` 才绘门扇代理；窗洞绘简化边框与不透明着色玻璃代理（非真实光学材质）。斜顶、曲墙、机电管线、真实门窗与家具细节不在本阶段自动推断。

## 最小示例

```json
{
  "schema_version": 1,
  "project": "synthetic-room",
  "units": "mm",
  "wall_height_mm": 2800,
  "rooms": [
    {
      "id": "R01",
      "name": "示例房间",
      "polygon": [[0, 0], [4000, 0], [4000, 3000], [0, 3000]],
      "wall_thickness_mm": 120,
      "walls": [
      {"openings": [{"kind": "door", "start_mm": 500, "width_mm": 900, "sill_mm": 0, "height_mm": 2100, "door_swing": {"hinge": "start", "side": "left"}}]},
        {}, {}, {}
      ]
    }
  ],
  "furniture": [
    {"id": "F01", "room_id": "R01", "name": "示意桌", "center_mm": [2000, 1500], "size_mm": [1200, 700, 750], "rotation_deg": 0}
  ]
}
```

家具占位的 `size_mm` 表示完整外包尺寸，`center_mm` 是平面中心、底面在地面。**新建或修改几何时必须显式填写 `type`**：`box`、`cabinet`、`table`、`mahjong_table`、`chair`、`armchair`、`sofa`、`bed`、`sink`、`toilet`、`refrigerator` 或 `cooktop`。校验/建模器仍将缺省 `type` 视为 `box` 以读取旧版文件；此兼容默认不适用于新数据，缺省会使Blender代理退化为通用方块且提示词类别不可靠。Blender中桌椅/沙发/床等盒体部件使用不超过12mm的倒角与加权法线改善轮廓；修改器不扩展申报外包尺寸，并会随GLB导出。`armchair` 为带双扶手的椅型代理，普通 `chair` 保持无扶手；沙发坐垫和靠背按座位数拆成匹配分块，以细缝提高辨识度，整体仍限制在输入外包尺寸内。`sink` 为柜体/台面/盆体，`toilet` 为水箱/底座/坐便圈，`refrigerator` 为柜体/门面/把手，`cooktop` 为台面机身/四个炉头标记；均为简化体块代理，不含真实开孔、管线、品牌型号、材质工艺或具体产品比例校核。朝向约定：toilet的水箱、refrigerator把手和门面朝局部-Y，旋转由 `rotation_deg` 控制；cooktop代理只表示占地及炉头排布。`rotation_deg` 绕Z轴旋转。DXF仍以外包矩形表达家具占位。

## 固定构件（可选）

柱、竖井、梁等只有在 CAD 明确或用户核实后才录入，不能因模型识图猜测。统一用旋转矩形体描述，其俯视占地同时写入参考 DXF，避免在布局与 3D 中漏掉已确认的避让物：

```json
"fixed_elements": [
  {"id": "C01", "room_id": "R01", "type": "column", "name": "CAD确认柱",
   "center_mm": [800, 700], "size_mm": [400, 400, 2800],
   "base_z_mm": 0, "rotation_deg": 0},
  {"id": "B01", "room_id": "R01", "type": "beam", "name": "CAD确认梁",
   "center_mm": [2000, 250], "size_mm": [3600, 250, 400],
   "base_z_mm": 2400, "rotation_deg": 0}
]
```

`room_id` 必须指向构件所在空间；`center_mm` 是平面中心，`size_mm` 为 `[宽, 深, 高]`，`base_z_mm` 是离地底标高，旋转绕 Z 轴。该简化版要求平面占地在所属房间内，且顶部不高于 `wall_height_mm`；跨房间梁需先拆分为各房间段或人工协调，不自动跨域归属。未在 CAD 确认的构件不得填写为事实。

## Blender 场景编辑结构

输出的 `.blend` 将对象放入 `室内方案` 根集合下，再按 `01_地面`、`02_墙体`、`03_家具占位`、`04_固定构件`、`05_门窗构件` 分类，并在每类内按房间分子集合（名称带类别序号与房间ID，避免重复命名后缀）。单个墙段、家具零件、门窗部件及固定构件均为独立对象；对象自定义属性含 `model_role`、`source_room_id`，墙段另含边号/分段号，家具/固定构件/门窗保留来源ID。GLB导出启用 glTF `extras`，将上述对象自定义属性保留为节点扩展元数据；Blender冒烟测试会回读每个家具代理零件并核验其角色、房间及家具来源ID。集合分组便于在 Outliner 中按类/房间隐藏、选择和编辑，但不使模型自动成为施工级或渲染就绪场景。

该格式与脚本生成结果用于方案沟通，不是施工图、结构判断或规范审查结论。
