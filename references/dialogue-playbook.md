# 室内设计小步交互演练

本指南把现有脚本串成对话工作流。它规定确认顺序和停点，不规定模型的设计创意；每次只推进用户当前要求的一项，展示该步产物后等待反馈。

## 先识别当前阶段

用户可能从任一阶段加入或只要求改一处。先判断本轮目标及已有可复用产物；不重做已验收步骤，不把后续阶段自动捆绑进来。

### 项目资料版本冲突

- 项目说明、计划、历史方案与当前交付物或用户最新确认不一致时，先核对用户确认、源CAD/截图版本、交付物本体及可用的版本/哈希信息。历史说明只作线索，不能覆盖较新的明确确认；CAD仍是几何与结构判断的最高图纸依据。
- 不因说明过期就重建或覆盖交付物。标出冲突及所依据的版本；若当前目标/版本仍无法确定，暂停该步，只问一个最小澄清问题。

### 新项目首轮最小输入

- 优先接收原始 CAD（DWG/DXF等）作为工程依据；若当前环境不能可靠读取，直接说明并请用户用免费CAD看图工具提供清晰截图，不把截图提升为高于CAD的结构依据。
- 需要一张完整楼层/区域的清晰截图用于现状图；保留外墙、门窗、楼梯、电梯、卫生间及房间隔墙，尽量包含能定位的图框或轴线。截图不清时一次只请用户补一张更清晰/更完整的图。
- 只问本轮继续所必需的信息：本次装修范围；若已有CAD和截图、范围也明确，就不要再发一份长问卷。
- 用户暂时没有设计要求时，只做图纸核对或现状图，不擅自做平面方案。需求信息可随讨论逐项补齐。
- 用户给出的CAD、截图及设计需求均保留来源和版本；CAD与用户明确确认优先于截图视觉猜测。不同版CAD/截图无法对应时先暂停几何工作。

| 阶段 | 本步交付 | 必须停下等待的确认 |
|---|---|---|
| 1. 原图与范围核对 | 核对CAD图、高清截图、装修边界、入口/楼梯/电梯/卫生间/柱墙等可见要素与不确定项 | 截图是否为完整正确楼层、装修范围是否明确；结构依据只引用CAD和用户明确标注 |
| 2. 现状图 | 从截图裁去外围无关区域或按需反相，保存源/输出哈希及裁切映射；生成与现状图同尺寸的双图层注释器 | 用户目检确认现状图没有缺掉外墙、隔墙、门窗、楼梯、电梯、卫生间等；不确定时要求补图/重截，不以补绘掩盖缺失 |
| 3. 读取布局批注 | 导出并校验注释器JSON；按图层、形状、坐标和文字逐条解释批注空间意图，展示索引和疑问 | 对每条影响几何的标注，用户确认模型理解；存在多种解释时逐条问，不继续把猜测写成房间/墙线 |
| 4. 建立尺寸约束 | 依据CAD或用户提供的尺寸选分布良好的像素-CAD锚点；至少4点拟合并留1个独立尺寸复核；产出带点号和来源ID的几何草稿 | 核对比例/误差、房间边界、共墙、开口、固定构件和家具位置；有未知项就保留空值并列出，不签发确认凭据 |
| 5. 平面方案确认 | 输出可切换对照图、方案说明所需最少文字及未决清单；必要时在注释器上迭代 | 用户确认精确版本的房间、洞口、墙边与家具几何；仅确认功能布局但未核对尺寸时，不算几何批准 |
| 6. DXF 参考图 | 用确认版 geometry JSON 生成简易DXF，回读毫米单位、图层、洞口/家具/固定构件实体与来源XDATA，并与模型顶投影叠加目检 | DXF是交设计师参考，不是施工图；用户确认本阶段交付后再进入3D，不默认为授权继续 |
| 7. Blender 草模 | 生成可编辑 `.blend`、GLB和本地资源齐全的浏览器页；核对房间连通、边界/开口/家具数量和尺寸，浏览器实测总览、房间聚焦、顶视/斜视、旋转/缩放 | 用户核对空间相对关系及家具大类；草模只需房间、通道、桌椅沙发可辨，不追求写实 |
| 8. imagegen 效果表现 | 先基于用户确认的模型和风格生成提示词及独立验收清单；用户明确要求效果图后，以对应Blender图为参考实际调用 Codex `imagegen`；多房间逐间生成，必要时可改用单张顶视图生成轴测草图 | 默认逐项对比同版Blender参考与清单；轴测草图只核对可见的平面关系，不据以确认高度/门扇；增删墙/门窗/家具、改变位置或遮挡到无法核验即退回，不把生成图反向当几何依据 |

## 批注解释规则

- 每条标注使用“图层 + 序号/像素范围 + 文字原文 + 图面对象”定位；文字不能脱离它圈住、指向或划分的空间单独解释。多条标注或容易歧义时，用[批注复核模板](../assets/annotation-review-template.md)在当前workspace留逐项回执；简单标注直接在对话里确认即可。
- 说明分三类：“用户明确表达”“模型理解（待确认）”“无法判定”。只对第一类落到下一步；第二类用简短复述向用户确认，第三类提出一个针对性问题或保持空白。
- 矩形/圆形可表示功能区、对象或范围，线可表示边界、方向或连接；不能仅凭工具类型赋予语义。不得擅自把圈选外延为边界、把线改成墙、把功能区直接变成房间几何。
- 用户确认某一标注的含义，不等于确认CAD尺寸、结构属性、整套几何、DXF、3D或效果图。每个阶段分别确认。
- 发现批注导出版本的 `project_id`、画布尺寸或底图哈希与当前图不一致，立即停止解释坐标，先找正确版本；禁止按视觉猜测配准。

## 对话节奏

每一轮回答只说：本步完成了什么、证据/链接、尚待确认的一个关键问题（如有）。不重复用户已说过的构想，不在完成一个步骤后展开长篇教程。用户说“继续”时只前进到流程中的下一道确认闸口；用户纠正后先更新当前产物，不继续下游。

若用户只要求分析、查看或指出差异，不写文件；若明确要求生成当前阶段产物，才执行对应脚本。任何真实项目的布局几何、批准凭据、DXF、正式模型或图像生成都必须来自当前项目输入及当前对话中的阶段授权；合成测试回执绝不用于真实项目。
