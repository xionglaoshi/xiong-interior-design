# 使用指南与排障

## 推荐工作路径

每轮只做用户当前指定的一步；交付后等待检查和反馈。不要把工具生成成功当作方案确认，也不要擅自从一阶段跳到下一阶段。

1. **拿到 CAD 高清截图**：确认图幅覆盖范围、楼梯/电梯、外墙、门窗、房间及固定设施可辨。截图只作视觉输入；CAD 原图和用户确认拥有更高证据效力。
2. **生成现状图**：先用 `prepare_existing_state.py` 做确定性方向规范化、裁切、黑底/灰度显示。需要模型清理外围杂线时，按 `current-state-image-workflow.md` 单独生成候选，三栏叠加核对并由用户确认后才绑定给注释器。
3. **注释讨论**：`build_floorplan_annotator.py` 从空白模板生成“现状图 / 平面布置图”同画布 HTML；平面布置图初始为现状图副本。用户在页面标注，导出 JSON。先解释标注指向的空间/功能意图和影响，再请用户确认含糊之处。不得恢复已取消的“结构图”层。
4. **整理为几何**：按 `annotation-to-geometry-workflow.md` 用 CAD/用户已确认的尺寸及边界建立 geometry JSON；标注来源单独追溯。来源不完整、像素坐标未校准、版本不一致时停止导出。
5. **参考 DXF / Blender**：只在当前几何版本获得用户明确确认、审核凭据有效后生成。DXF 用作简易参考；Blender 用于浏览空间关系，家具仅为占位代理。`.blend`、GLB 和浏览器页面同版输出并通过回读/交互测试。
6. **imagegen 表现图**：只在用户另行指令后，按 `render-prompt-workflow.md` 为已确认模型生成图像参考与逐项验收清单。imagegen 不是几何引擎；关键边界/门窗/家具错误则退回，不得用修辞掩盖。

## 常见问题与处理

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 现状图灰蒙、线条发浅 | 深色 CAD 截图按原色保留或显示器缩放 | 先查看原 PNG；按需用 `--tone cad-dark`。不要靠重绘提黑，以免改线 |
| AI 清洗图一片白、比例变了或整体偏移 | 输入没有作为编辑目标；模型重绘/改变输出分辨率或重构线条 | 核对源/目标路径和哈希；只接受长宽比差 ≤0.1% 的显式等比规范化；看叠加，任何位移/遗漏即拒绝，退回确定性截图 |
| 轴网线清不掉 | 杂线贴近或穿过平面实体，自动去线风险高 | 只裁掉图纸外边缘；歧义线保留并请用户确认，不做连通域删除或猜测性擦除 |
| 注释器切换看起来不是同一张图 | 两张底图尺寸/裁切不一致，或页面缓存旧版本 | 确保两层画布尺寸相同；构建器不负责自动配准。确认打开的是当前绝对路径/新版本，强制刷新以排除浏览器缓存 |
| 页面标注没有写进 HTML | 页面批注通常保存在浏览器本地存储，源 HTML 不会自动被改写 | 在注释器中导出 JSON；保留原文件并按 JSON 汇总。需要搬迁时用页面的 JSON 导入/导出 |
| 批注文字读到了但意图不确定 | 几何对象/功能约束需要空间语境，OCR 只提取字面 | 对照标注目标和附近空间，描述可能意图及影响；有歧义就列为待确认，不能直接改 geometry |
| DXF 打开是空白或缩放范围不对 | CAD 读取 `$EXTMIN/$EXTMAX` 或默认范围异常 | 当前导出器已设置公制范围并回读 audit；检查确实打开新导出的 DXF，再执行 CAD“范围缩放”。仍不对时保留文件并检查实体/范围，不手改原输入 |
| DXF 和 Blender 叠加错位 | DXF 与 `.blend` 来自不同几何版本或元数据缺失 | `audit_dxf_blender_overlay.py` 需要匹配 geometry SHA；回到同一个已确认 JSON 重导，不得把异版叠图当几何缺陷 |
| Blender 文件能导出但房间/家具看不清 | 相机遮挡、房间边界过复杂或代理模型简单 | 试用顶视与斜视、按房间聚焦；运行相机/浏览器回归。调整观察机位不能改几何；家具代理不可冒充精细产品模型 |
| 浏览器 3D 页面打不开/模型不出现 | `file://` 跨域限制、依赖/GLB 缺失或损坏 | 用输出包 `使用说明.md` 的本地服务方式；检查同目录 GLB、`model-viewer` 脚本及许可文件；错误态应给出页面提示，浏览器回归不得请求外网 |
| Imagegen 补了墙、门或出现拼贴 | 模型会补全未输入细节，复杂参考容易混图 | 一次只生成一个房间、一张图；约束为单视角；对照 Blender 几何核验图。关键洞口/比例有错就不通过 |
| 脚本拒绝覆盖或审批 | 目标已存在、输入内容哈希变化、凭据针对旧版本 | 使用全新版本输出目录；不要随手加 `--force` 或重用旧凭据。重新审计并请用户确认最新精确版本 |

## 能力探查与验证

- 先阅读相应 reference，再检查 `scripts/` 现有功能和测试，避免重新开发已有能力。
- 用合成夹具验证接口/边界，但报告中标明“合成测试”；真实项目能力需要真实输入、人工目检和用户验收。
- 运行全量测试入口：

  ```sh
  cd "${CODEX_HOME:-$HOME/.codex}/skills/xiong-interior-design"
  python3 scripts/run_skill_tests.py
  ```

- 浏览器页面变化应运行相应隔离 Chrome 测试；Blender场景/相机变化应通过 Blender 5.2.2 后台测试；来源和导出变化必须检查哈希、坐标及失败时无残留。
- 单测通过只证明受测行为。它不代表原始 CAD 内容完整、布局可施工、承重判断正确、消防合规或 imagegen 输出几何保真。
